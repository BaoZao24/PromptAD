
## 总体评价

该实验部分的优点是：明确采用目标场景 normal-only 冷启动设定，分别报告 AUROC、AP 和 FPR@95%TPR，并对 RF 异常类型和 OFDMA jammer 类型进行了拆分分析。实验结果表明双分支融合相较 ViT 单分支确实存在一定提升。

但目前实验尚不足以严格证明 **Confidence Fusion 本身有效**。最关键的问题是早期置信度计算可能使用了测试批次的分布信息，且实验缺少随机重复、置信区间和关键融合消融。在当前版本下，我倾向于给出 **Major Revision**。以下意见按照重要性排序。

---

## 1. 置信度计算可能存在测试阶段信息泄漏或不现实的 transductive 设置

这是当前最严重的问题。

第 1 页写道，对“同一个无标签测试单元”的分数进行 min-max 归一化，并计算 CNN 的“单元内百分位排名”。但目前没有说明“测试单元”的确切边界：

- 是一个完整测试集；
- 一个 anomaly type-JSR 单元；
- 一个频段；
- 一个采集批次；
- 还是一个场景中的全部观测。

如果 RF 中的置信度计算是在“异常类型-JSR 单元”内部计算排名，那么即使没有直接读取二分类标签，划分该单元本身也使用了异常类别和 JSR 信息，而这些信息在真实部署时通常不可获得。这实际上构成了 oracle grouping。

即使测试单元不使用异常标签，只要一个样本的异常分数依赖同批其他测试样本的最大值、最小值和百分位分布，该方法仍然属于 transductive batch inference，而不是通常意义上的独立样本推理。最终分数还会随着测试批次大小、异常比例和异常强度组成发生变化。

建议必须补充：

1. 明确定义 RF 和 OFDMA 中“测试单元”分别是什么。
2. 说明归一化和百分位计算是否使用了整个测试集合。
3. 增加严格 inductive 版本：仅使用正常 support 建立分数参考分布，例如基于 support 增强样本或 leave-one-out normal scores 构建经验 CDF。
4. 比较：
   - test-batch rank；
   - support-only rank；
   - 固定源域校准；
   - 单样本在线推理。
5. 测试不同批次大小和不同异常占比对结果的影响。

如果该问题无法解决，论文应该把任务明确描述为“批次级 transductive 异常检测”，而不能笼统称为冷启动异常检测。

## 2. 少样本实验没有随机重复，当前增益可能落在 support 采样方差内

论文在局限性中承认，RF 使用固定的 per-frequency support，未报告多随机种子的置信区间。这不是一般性局限，而是少样本实验中必须解决的核心实验问题。

目前主要增益并不大：

- self RF 相对 PromptAD 提升 2.07 个 AUROC 点；
- public RF 提升 3.11 个点；
- OFDMA 2-shot 仅提升 0.67 个点；
- OFDMA 4-shot 提升 0.98 个点。

在 1-shot 或少样本设置中，更换一张 support 图像完全可能造成数个百分点的波动。因此，现在无法判断这些提升来自方法，还是来自特定 support 选择。

建议进行一个小规模但可复现的稳定性检查，不必进行大规模随机搜索：

- RF 使用 **5 个独立 support seed** 进行重复；如果 5 次结果的区间明显过宽，再增加到
  10 次作为补充，而不是一开始要求 20～30 次；
- OFDMA 使用 **3 个独立 support seed**，每个 seed 统一评估 1/2/4-shot，不要求对每个
  场景再单独进行多轮随机试验。若每个场景的正常 support 数量恰好等于 4，则 4-shot
  本身只有一个不放回组合，应明确报告这一事实，不把同一组合重复计作独立样本；
- 报告 mean ± std 或 95% confidence interval；
- 使用 paired bootstrap 或配对统计检验，因为所有方法应使用相同 support 抽样；
- 对 30 个 OFDMA 场景进行场景级 bootstrap，而不是把所有观测直接混合。该 bootstrap
  只是统计重采样，不会增加模型运行次数。

图 1、图 3、图 4、图 5 和图 6也应增加误差棒或置信区间。否则很难判断图中不足 1 个百分点的差距是否具有统计意义。

## 3. 核心融合模块的消融实验明显不足

第 3 页的消融只比较了：

- ViT normal memory；
- CNN normal memory；
- ViT + CNN confidence fusion。

这只能证明“加入 CNN 信息后结果变好”，不能证明提出的 confidence fusion 比普通融合方法更好。因此必须直接与简单融合策略比较。

至少应增加以下消融：

| 设置                    | 目的                     |
| ----------------------- | ------------------------ |
| \(v\)                   | ViT 基线                 |
| \(c\)                   | CNN 基线                 |
| \((v+c)/2\)             | 固定平均融合             |
| \(\max(v,c)\)           | 最大值融合               |
| \(1-(1-v)(1-c)\)        | Direct probabilistic OR  |
| 固定加权\(v+\lambda c\) | 排除简单调权即可获得提升 |
| 仅使用\(c-v\) 条件      | 验证百分位排名的作用     |
| 仅使用排名条件          | 验证分支差值条件的作用   |
| 完整 confidence fusion  | 完整方法                 |

还应报告 confidence correction 分位数 \(q\) 的敏感性，例如 \(q=0.25,0.5,0.75,0.9\)。目前直接固定 \(q=0.5\)，缺少实验依据。

如果普通 max 或 probabilistic OR 就能达到相近结果，那么当前 confidence fusion 的创新价值会明显降低。

## 4. 对比实验的公平性和实现细节不充分

论文称所有方法都在相同 normal-only evaluator 中完成，但“相同 evaluator”并不等于公平比较。需要说明：

- 输入图像尺寸和预处理是否一致；
- 每个方法使用多少张 support；
- backbone 和预训练权重；
- 是否冻结特征提取器；
- 是否使用数据增强和 TTA；
- 超参数搜索范围；
- 是否针对每个数据集单独调参；
- VAE、SAIFE 和 Deep SVDD 在 1-shot 下如何训练；
- PromptAD 的文本 prompt、模板数量和类别词如何设置；
- 是否所有方法均未查看目标异常数据。

尤其是 VAE、SAIFE、Deep SVDD 这类训练型方法，在每个频段只有一张正常图时从头训练，天然处于极不利条件。需要说明是否进行了预训练、增强或跨频段训练，否则这些低结果不能构成有说服力的比较。

此外，PatchCore 在 RF 上是较强基线，但在 OFDMA 表格中缺失。文中应明确解释为什么无法评估，或者补充结果。考虑到本文的 ViT 和 CNN 分支本质上均采用正常特征 memory 与最近邻评分，一个采用相同 backbone、相同特征层和相同 support 的 PatchCore/nearest-neighbour baseline 尤其重要。

## 5. 大量超参数和规则缺少独立验证协议

当前方法包含很多人为设定：

- ViT layer1 + layer2；
- CNN ResNet18 layer3；
- coreset 比例 0.5；
- top-k = 5；
- 四个 STFT 视图；
- 3×3 模糊；
- 时间轴 ±4 pixel；
- \(q=0.5\)；
- OFDMA 使用第三高 patch；
- 21 个 SU 使用最大值聚合。

目前未说明这些参数如何确定。如果这些选择是在 self RF、public RF 或 OFDMA 测试结果上反复试验后确定，则存在 test-set tuning。

作者需要明确：

1. 是否存在独立验证集；
2. 验证集是否包含目标异常；
3. 不同数据集是否使用同一组预先固定的参数；
4. 参数是在源数据集上选择，还是在目标测试集上选择。

建议至少补充以下敏感性分析：

- coreset：0.1、0.25、0.5、1.0；
- top-k：1、3、5、10；
- \(q\)：多个分位数；
- 无 TTA、模糊 TTA、平移 TTA、全部 TTA；
- patch 聚合：最高、第三高、前 5 平均；
- SU 聚合：max、top-k mean、mean、log-sum-exp。

## 6. 数据划分与数据集构造描述不足，无法排除背景泄漏

self RF 和 public RF 目前只给出了异常类别以及 macro 单元数量，但缺少基本数据统计：

- 每个单元的正常和异常图像数量；
- 不同 JSR 的具体取值；
- 频段数量；
- support 和 test 是否来自不同采集时间；
- 是否来自相同设备、天线和接收链路；
- 相同信号波形或相同录制片段是否跨 support/test 出现；
- public RF 数据集的来源、版本和划分方式；
- 是否存在同一长时序记录切片后分别进入 support 与 test 的情况。

频谱图异常检测很容易学习设备噪声、绘图方式、背景功率或采集 session，而不是异常本身。建议增加更严格的划分：

- leave-session-out；
- leave-device-out；
- leave-frequency-band-out；
- 未见过的 JSR；
- 未见过的异常参数或波形配置。

OFDMA 数据中，同一场景正常上下文保持一致，只改变合法数据符号、时隙活动和小幅扰动。这种构造可能使异常检测问题过于理想化。除了真实采集，至少应加入跨场景 support-test、较大功率漂移、不同信道衰落、频偏、定时偏差和接收机参数变化实验。

## 7. 对 deceptive 信号的结果仍然较弱，与论文目标可能不一致

第 4 页中，public RF deceptive 的 AUROC 只有 55.23%，接近随机水平。尽管比 PromptAD 的约 45% 更高，但这一结果仍不能说明该类异常已被有效检测。

如果论文主要动机之一是识别 deceptive 信号，那么平均 AUROC 的提升会掩盖关键类别上的失败。建议补充：

- 每种异常的 AUROC、AP 和 FPR95，而不是只报告 AUROC；
- deceptive 的置信区间；
- 正常与 deceptive 的分数分布；
- 不同 JSR 下的 deceptive 性能；
- 检出率-误报率曲线；
- 若要求低误报，报告 TPR@1%FPR 或 TPR@5%FPR；
- 成功和失败样例的 anomaly map；
- ViT、CNN、融合方法在 deceptive 上的分别表现。

此外，self RF deceptive 为 82.65%，public RF 却只有 55.23%，这一明显下降可能说明方法依赖数据集特定的纹理或背景，需要重点讨论跨数据集泛化问题。

## 8. macro 指标与 pooled 曲线存在较大差异，容易造成误导

表 1 的正式指标为测试单元宏平均，但图 2 使用 pooled ROC 和 pooled PR：

- self RF：macro AUROC 92.59%，pooled AUROC 94.71%；
- public RF：macro AUROC 82.18%，pooled AUROC 88.39%。

public RF 相差超过 6 个百分点，说明不同测试单元之间存在明显难度差异，pooled 指标可能被样本更多或更容易的单元主导。

建议：

- 主文优先展示 macro 指标对应的分布，例如每个单元 AUROC 的箱线图或 violin plot；
- pooled 曲线只能作为辅助可视化，并在图中明显标记“not directly comparable with Table 1”；
- 或通过对各单元 ROC 插值后绘制 macro-average ROC，并同时显示置信带；
- 报告各 anomaly-JSR 单元的完整结果或至少均值、中位数、最差四分位数。

另外，AP 强烈依赖异常比例。论文应报告每个数据集和单元中的 normal/abnormal 比例，并统一使用“AP”或“AUPRC”术语。

## 9. FPR@95%TPR 的估计稳定性和实际意义需要加强

OFDMA 每场景只有 100 个 normal，因此 FPR 的分辨率约为 1%。每类 jammer 只有 20 个观测，95% TPR 对应几乎只允许漏掉 1 个样本，阈值估计会比较不稳定。

建议：

- 对 FPR95 报告 bootstrap 置信区间；
- 同时报告 TPR@1%FPR、TPR@5%FPR 或 partial AUROC；
- 说明 ROC 阈值的插值方式；
- 明确存在并列分数时如何计算；
- 增加基于正常 support 或独立 normal validation set 的固定阈值实验。

异常检测部署中通常不能根据包含异常的完整测试集事后选择达到 95% TPR 的阈值，因此最好增加“仅根据正常数据设定阈值”的实际运行指标。

---

## 10. OFDMA 的两级聚合规则需要单独验证

OFDMA 中先取 anomaly map 的第三高 patch，再对 21 张 SU 图取最大值。该策略对结果影响可能很大，却被称为“固定观测聚合协议”，没有充分实验支持。

最大值聚合会随着 SU 数量增加而自然提高正常观测出现极端分数的概率，因此可能显著影响 FPR。建议增加：

- 第一高、第三高、第五高 patch；
- top-3/top-5 patch 均值；
- 21 SU 的 max、mean、top-k mean 和 log-sum-exp；
- SU 数量变化实验；
- jammer 影响单个 SU 和多个 SU 时的分项结果。

还需要说明五类 jammer 分别影响多少个 SU，以及观测标签的定义方式。

---

## 11. 缺少计算复杂度和实际部署代价

本文方法同时使用 ViT、CNN、四视图 ViT TTA、最近邻 memory，并且 OFDMA 每个观测包含 21 张 SU 图。相较单分支方法，推理开销可能明显增加。

建议报告：

- support memory 建立时间；
- 单张 RF 图的推理时间；
- 单个 21-SU OFDMA 观测的推理时间；
- GPU/CPU 型号；
- 峰值显存；
- memory bank 大小；
- coreset 前后特征数量；
- 与 PromptAD、PatchCore 和 ViT-only 的速度比较。

如果双分支只提升约 1～3 个百分点，但计算量增加数倍，应讨论其性价比。

## 12. 当前“复现入口”不足以支持论文复现

第 4 页列出的 `analysis_outputs/...` 和 `unified_results.csv` 是本地目录路径，外部审稿人无法访问，不能被视为复现材料。

正式论文至少应提供：

- 匿名代码仓库或补充材料；
- 完整配置文件；
- 数据划分文件；
- 随机种子；
- pretrained checkpoint 信息；
- STFT 参数、图像分辨率和归一化方式；
- 每个 baseline 的训练轮数、优化器和学习率；
- 从原始结果生成表格和图片的脚本。

如果数据暂时不能公开，应明确说明可公开的代码、合成数据生成器和数据划分索引。

## 次要修改意见

1. “self RF”和“In-house RF”应统一命名。
2. “AP”和“AUPRC”应统一。
3. “FPR95”和“FPR@95%TPR”应统一。
4. 公式中应完整说明 min-max 归一化的范围，以及当最大值等于最小值时如何处理。
5. 说明百分位排名中并列分数的处理方式。
6. 表 2～4应同时标出最优和次优结果，并明确 1-shot 下本文方法并非最优。
7. 图 5 不应只展示与 PromptAD 的比较，至少应加入 ViT-only，以观察 deceptive 的提升究竟来自 CNN 还是 confidence fusion。
8. 图 4与表 5信息基本重复，可以用更有价值的融合消融图替代。
9. 图 3中部分方法结果接近，建议加入误差棒，否则折线差异的解释意义有限。
10. “不能把两套数据合并后计算 ROC”属于合理原则，但应进一步说明所有方法是否完全遵循相同的单元划分和宏平均过程。

## 建议作者优先补充的五组实验

按照最低必要程度，建议优先完成：

1. **support-only 校准与当前 test-batch 校准的比较**，排除测试信息泄漏。
2. **多次随机 support 重复及置信区间**。
3. **平均、最大值、Direct OR、固定加权与完整 confidence fusion 的消融**。
4. **统一配置下的公平 baseline 比较，并补充 OFDMA PatchCore**。
5. **deceptive 的逐 JSR、AP、FPR95、分数分布和失败案例分析**。

完成前四项后，才能较可靠地判断 Confidence Fusion 的实际贡献。
