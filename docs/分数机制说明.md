# 分数机制说明

这份文档说明仓库中上游 `cls` 代码的各类分数，以及当前论文主线最终采用的
support-only visual score。前半部分保留 PromptAD 文本/视觉接口的代码导读，但文本
分数不属于当前 RF、OFDMA 或 FedJam 论文主表；当前主线以第 8 节的 ViT normal memory、
CNN local memory 和 Confidence Fusion 为准。

## 1. 总体结构

当前 `cls` 任务的图像级异常分数，主链路是：

```text
输入图像
-> CLIP 图像编码器
-> 文本分支给出图像级 textual anomaly score
-> 视觉分支给出 patch 级 visual anomaly map
-> 可选地把 visual anomaly map 聚合成图像级 visual score
-> 按配置融合成最终 image score
```

对应代码主入口在：

- [PromptAD/model.py](/mnt/data/wangbei/PromptAD/PromptAD/model.py:1987)
- [train_cls.py](/mnt/data/wangbei/PromptAD/train_cls.py:439)

默认配置下，`Image-AUROC` 主要还是看文本分支给出的图像级分数；视觉分支更多是给异常图和可选融合使用。

## 2. 图像编码后会得到什么

`encode_image()` 会返回多路视觉特征，当前代码里主要用到 4 路：

```text
visual_features[0] : 全局图像特征，用于 cls 文本分数
visual_features[1] : 局部 token 特征，用于 seg 文本异常图
visual_features[2] : patch feature map 1，用于视觉 memory-bank 分数
visual_features[3] : patch feature map 2，用于视觉 memory-bank 分数
```

对应说明在：

- [PromptAD/model.py](/mnt/data/wangbei/PromptAD/PromptAD/model.py:2009)

## 3. 文本分支分数

### 3.1 `single` 模式

默认思路是把图像特征和文本原型做相似度比较。

先有两个文本原型：

```text
text_features[0] = normal prototype
text_features[1] = abnormal prototype
```

图像级 `cls` 分数计算是：

```text
logits = logit_scale * global_feature @ text_features^T
score = softmax(logits)[abnormal]
```

对应代码：

- [PromptAD/model.py](/mnt/data/wangbei/PromptAD/PromptAD/model.py:1868)
- [PromptAD/model.py](/mnt/data/wangbei/PromptAD/PromptAD/model.py:1894)

也就是说，默认图像级文本分数本质上是：

```text
图像更像 abnormal prototype 的概率
```

### 3.2 grouped 多异常原型模式

如果 `text_prototype_mode` 不是 `single`，而是：

```text
grouped_max
grouped_mean
grouped_meanmax
grouped_softmax
```

则文本原型会变成：

```text
text_features[0] = normal
text_features[1] = burst abnormal
text_features[2] = chirp abnormal
text_features[3] = dsss abnormal
```

先算每个异常组相对 normal 的 margin：

```text
margin_k = sim(image, abnormal_k) - sim(image, normal)
```

然后不同模式对应不同聚合：

#### `grouped_max`

```text
score = sigmoid(max_k(margin_k))
```

#### `grouped_mean`

```text
score = sigmoid(mean_k(margin_k))
```

#### `grouped_softmax`

```text
weight_k = softmax(margin)_k
score = sigmoid(sum_k weight_k * margin_k)
```

#### `grouped_meanmax`

这里不是先对 margin 做平均，而是先转成每个原型自己的概率：

```text
proto_score_k = sigmoid(margin_k)
score = 0.5 * mean_k(proto_score_k) + 0.5 * max_k(proto_score_k)
```

对应代码：

- [PromptAD/model.py](/mnt/data/wangbei/PromptAD/PromptAD/model.py:1818)
- [PromptAD/model.py](/mnt/data/wangbei/PromptAD/PromptAD/model.py:1875)

### 3.3 patch 级文本异常图

`seg` 分支也是类似逻辑，只不过输入不是全局特征，而是 patch/token 特征：

```text
token_features -> 和文本原型比较 -> 得到每个 patch 的 abnormal score
```

对应代码：

- [PromptAD/model.py](/mnt/data/wangbei/PromptAD/PromptAD/model.py:1821)

## 4. 视觉分支分数

视觉分支不是靠文本，而是靠“当前 patch 和正常 patch 库有多不像”。

### 4.1 正常 gallery 怎么来

训练开始前，会把正常训练样本送进图像编码器，缓存两路 patch 特征：

```text
feature_gallery1
feature_gallery2
```

对应代码：

- [train_cls.py](/mnt/data/wangbei/PromptAD/train_cls.py:313)
- [PromptAD/model.py](/mnt/data/wangbei/PromptAD/PromptAD/model.py:1783)

### 4.2 patch 级视觉异常分数怎么来

测试时，每个 patch 去正常 gallery 里找最近邻，距离越大，异常分数越高。

具体是：

```text
score1 = min_j (1 - cos(feature_map1_patch, gallery1_j)) / 2
score2 = min_j (1 - cos(feature_map2_patch, gallery2_j)) / 2
visual_patch_score = 0.5 * (score1 + score2)
```

对应代码：

- [PromptAD/model.py](/mnt/data/wangbei/PromptAD/PromptAD/model.py:1908)

得到的是一张 patch 级视觉异常图 `visual_anomaly_map`。

## 5. 图像级视觉分数怎么聚合

如果要把视觉异常图变成图像级分数，当前支持几种聚合。

先把 patch 分数拉平，然后取 top-k：

```text
topk = max(1, patch_count * visual_topk_ratio)
mean_topk = top-k patch score 的平均
max_score = 所有 patch score 的最大值
```

如果启用了频率位置加权，还会对频率方向的 patch 分数做额外权重。

对应代码：

- [PromptAD/model.py](/mnt/data/wangbei/PromptAD/PromptAD/model.py:1938)

### 支持的 `cls_score_mode`

#### `text_only`

```text
final_score = textual_anomaly
```

这是当前最常见的默认模式。

#### `visual_topk`

```text
visual_score = mean_topk
final_score = alpha * textual_anomaly + beta * visual_score
```

#### `visual_topk_max`

```text
visual_score = beta * mean_topk + gamma * max_score
final_score = alpha * textual_anomaly + visual_score
```

#### `visual_topk_freq`

实现上和 `visual_topk_max` 共用同一段融合逻辑，区别主要在视觉聚合时已经对频率位置做了加权。

## 6. `score_cached()` 这一层实际返回什么

评估时真正被调用的是：

- [PromptAD/model.py](/mnt/data/wangbei/PromptAD/PromptAD/model.py:1987)

它会同时做两件事：

1. 计算图像级分数 `image_scores`
2. 计算像素/patch 级异常图 `anomaly_map`

返回值是：

```text
am_img_list : 每张图的图像级分数
am_pix_list : 每张图的异常图
```

所以当前项目里的 `scores_img` 用于算 `Image-AUROC`，`score_maps` 主要用于可视化和像素级分析。

## 7. 评估时还有两个可选加分支

### 7.1 传统频谱统计分数融合 `stat_fusion`

如果启用 `stat_fusion`，会额外从原始图像上计算一个传统统计分数：

```text
freq_background = 沿频率方向的中位数背景
residual = |gray - freq_background|
local_std = 局部标准差
stat_map = 0.5 * residual + 0.5 * local_std
stat_score = stat_map top-k 均值
```

然后和图像级分数做线性融合：

```text
final_score = image_score + beta * stat_score
```

对应代码：

- [train_cls.py](/mnt/data/wangbei/PromptAD/train_cls.py:206)
- [train_cls.py](/mnt/data/wangbei/PromptAD/train_cls.py:228)
- [train_cls.py](/mnt/data/wangbei/PromptAD/train_cls.py:458)

### 7.2 Paired TTA patch-gallery 融合

旧的 `multiview_fusion` 路线已经废弃。它只对测试图做多个输入视图，再融合
PromptAD 原始 `score_img / score_map`，容易和当前 patch-gallery 主线混淆。

当前保留的是 `paired_tta` 路线：

```text
normal support 图和 test query 图同步做同一种安全变换
-> 每种变换单独建立 normal patch gallery
-> query patch 只和同视图 gallery 比较
-> 得到多张 patch anomaly map
-> 用 max / mean 融合 anomaly map
```

当前实验使用：

```text
--paired-tta visionad_safe
--paired-tta-fusion max
```

包含的安全视图：

```text
identity
contrast
blur
crop
```

也可以使用 STFT 语义更明确的变体：

```text
--paired-tta stft_shift_blur
--paired-tta-fusion max
```

它将 `contrast/crop` 替换为上下双向时间轴轻微平移：

```text
identity
blur
time_shift_up
time_shift_down
```

默认平移幅度：

```text
--paired-tta-shift-px 4
```

这条线的动机是：STFT 图的时间轴轻微上下移动通常不改变异常语义，比裁剪更容易解释。

三类 smoke（burst / pulse / dsss）中，`stft_shift_blur` 优于 `visionad_safe`
和单向 time-shift 版本，因此保留为当前 STFT-specific paired TTA 候选。

曾短暂验证过 `identity + weak_residual` 作为 RF 专用 paired TTA 视图。该方案本质上是
直接构造功率残差并取高分位置，不属于真正的 Paired-TTA，因此已从当前 TTA 设计中舍弃；
相关结果只保留为独立功率残差分支的历史探索记录。

`visionad_safe` 不是测试时反向更新参数的 TTA，而是 support-query 成对多视图评估。

## 8. 当前现状

当前 RF 主线不使用 PromptAD text score 作为最终图像级分数，而是以 ViT normal memory 为基础，再用 CNN 局部证据进行置信度融合：

```text
ViT patch normal memory -> ViT anomaly score
CNN local normal memory -> CNN anomaly score + confidence
ViT score + confidence-calibrated CNN evidence -> final image score
```

两条 normal memory 的匹配规则有意不同。ViT patch 具有较大感受野，正常 patch
之间重复度高，因此使用 farthest-first coreset 保留结构多样性，并用 top-k
近邻平均降低单个近邻的偶然性。CNN patch 更强调局部亮线和细弱能量变化，保留完整
local memory 并使用单最近邻，可以避免 coreset 删除少见的正常局部模式，也避免
top-k 平均削弱小区域异常。CNN 只是辅助证据，最终补充量由无标签 confidence
rule 决定。

正式 support-only 置信度融合不使用 target abnormal、测试标签或其他测试样本，
只使用正常 support 参考视图计算相对排名：

```text
z_v = (vit_score - median(vit_support)) / (IQR(vit_support) + eps)
z_c = (cnn_score - median(cnn_support)) / (IQR(cnn_support) + eps)
p_v = sigmoid(z_v / 2.5)
p_c = sigmoid(z_c / 2.5)
rank = support_empirical_rank(cnn_score, cnn_support)
confidence_correction = indicator(rank >= 0.8) * max(p_c - p_v, 0)
final = vit_score + 2.5 * IQR(vit_support) * confidence_correction
```

因此只有 CNN 在正常 support 参考分布中位于高分段、且证据强于 ViT 时才增强最终
分数。最终分数不会因测试批次大小或异常比例改变，可以逐张图在线计算。旧的批次级
校准规则只保留在协议对照输出中，不作为正式方法。

## 9. 为什么接下来可以重点考虑 patch score

当前任务里，很多异常本质上是局部弱结构：

- 一条很弱的斜线
- 局部突发竖条
- 一小片扩散纹理扰动
- 某些 patch 上的局部能量异常

这类异常未必会强烈改变整张图的全局语义，但往往会先体现在一小部分 patch 上。

因此，单纯依赖全局文本分数会有一个天然限制：

```text
全局图像特征更像是在回答：
“整张图整体像不像 abnormal prototype”
```

而 patch score 更像是在回答：

```text
“这张图里是否存在少量明显偏离正常分布的局部区域”
```

从异常检测角度看，后者其实更贴近弱异常的本质。

所以，接下来一个很自然的改进方向就是：

> **把 patch 级视觉异常分数更正式地聚合成图像级分数，并用于提升 `Image-AUROC`。**

这条思路的好处是：

1. 不依赖异常类型先验
2. 不依赖 prompt 写法
3. 更贴近频谱弱异常的局部结构特点
4. 可以直接复用当前已经算出来的 `visual_anomaly_map`

## 10. 我们接下来可以怎么做

最直接的做法不是重新设计整套模型，而是先改图像级分数聚合。

也就是说，把：

```text
patch-level visual score map
```

通过某种聚合规则变成：

```text
image-level patch score
```

再把它用于 `Image-AUROC`。

当前代码里已经有基础入口：

- [PromptAD/model.py](/mnt/data/wangbei/PromptAD/PromptAD/model.py:1938)
- [PromptAD/model.py](/mnt/data/wangbei/PromptAD/PromptAD/model.py:1969)

因此后面最值得优先尝试的是这些方向：

1. **只用 patch score 做图像级分数**
   ```text
   final_score = visual_topk_score
   ```

2. **文本分数 + patch score 融合**
   ```text
   final_score = alpha * text_score + beta * patch_score
   ```

3. **top-k 与 max 的组合**
   ```text
   final_score = alpha * text_score + beta * topk_mean + gamma * max_patch
   ```

4. **频率加权的 patch 聚合**
   如果我们认为某些频率位置更重要，可以对 patch score 做频率方向加权后再聚合。

这几条都属于“分数层改进”，代码改动小，而且直接对应 `Image-AUROC`。
