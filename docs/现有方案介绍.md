# RF 提示词与灰度残差频谱特征融合方案

## 1. 方案概述

当前采用的完整方案由两部分组成：

```text
prompt_mode = rf
input_mode = morph_fusion_gray_residual_a01
```

其中，`prompt_mode=rf` 用于把 PromptAD 原本面向通用视觉异常的文本提示词改为射频频谱场景提示词；`morph_fusion_gray_residual_a01` 用于在输入端对频谱图进行三通道重构，将原始 RGB 输入替换为更符合频谱异常检测任务的灰度结构表示。

因此，本文的主线不是单独声称“只改特征图”，而是将原始 PromptAD 适配为：

```text
原始 PromptAD -> RF 场景提示词 + 频谱结构灰度输入
```

方案示意图如下：

![方法流程图](analysis_outputs/current_scheme_figures/gray_residual_pipeline.png)

输入三通道定义如下：

```text
morph_fusion_gray_residual_a01 = gray_contrast + weak_residual(alpha=0.1) + original_gray
```

也就是说，模型输入不再依赖频谱图的伪彩色 RGB 映射，而是同时包含灰度强度、相对背景偏离和原始灰度保真信息。

## 1.1 本文方案的核心贡献

本文当前真正成立的贡献不是“试了很多特征图”，而是把 PromptAD 系统性地改造成了更适合频谱异常检测的形式：

1. **文本侧贡献**：提出 `prompt_mode = rf`，把原始 PromptAD 面向通用工业缺陷的提示词，替换为面向射频频谱异常的语义描述。
2. **输入侧贡献**：提出 `morph_fusion_gray_residual_a01`，用 `gray_contrast + weak_residual(alpha=0.1) + original_gray` 组成统一三通道输入，替换原始 RGB。
3. **协议侧贡献**：重新定义真正 baseline 为 `legacy + RGB`，并在自测数据、公开 `RF_SPE_PNG` 和 `spectrum` 数据集上分别完成对比，避免把中间消融设置误写成 baseline。

因此，这个方法的贡献点是“RF 场景语义适配 + 统一频谱结构输入”，而不是只靠某一个单独小技巧。

## 1.2 取得的主要提升

当前最重要的结果有三组：

- **自测主实验**：三类平均 Image-AUROC 从 `87.4175` 提升到 `90.5650`，提升 `+3.1475`。
- **公开 RF_SPE_PNG 补充验证**：在新的混合协议下，九条总体均值从 `78.27` 提升到 `80.37`，提升 `+2.11`。其中 `burst` 和 `chirp` 都保持稳定正收益。
- **spectrum 数据集补充验证**：四类平均从 `95.5800` 提升到 `96.9750`，提升 `+1.3950`。
- **VCP dense map 补充诊断**：在 Image score 固定为原 PromptAD 分支的前提下，VCP/dense map 将跨库 Pixel-AUROC 从 `53.28` 提升到 `61.87`，提升 `+8.59`。

从这些结果看，当前方法最稳定的收益来源是：让文本原型更符合 RF 异常语义，同时让图像输入更接近频谱结构本身，而不是继续依赖伪彩色映射。

## 2. RF 提示词改进

### 2.1 改在哪里

RF 提示词的改动发生在文本分支，不改 CLIP 图像编码器主体。代码路径如下：

| 位置 | 作用 |
|---|---|
| `train_cls.py` | 通过 `--prompt-mode rf` 选择 RF 提示词模式 |
| `PromptAD/ad_prompts.py` | 定义 RF 类名映射和 RF 异常描述模板 |
| `PromptAD/model.py` | 在 `PromptLearner` 中把模板拼成 normal prompt、手工 abnormal prompt、可学习 abnormal prompt |

训练时使用：

```text
prompt_mode = rf
```

对应到代码中，`train_cls.py` 会把 `prompt_mode` 传入模型；`PromptAD/model.py` 的 `PromptLearner` 再调用：

```text
get_prompt_classname(classname, dataset_name, prompt_mode)
get_abnormal_prompt_states(classname, dataset_name, prompt_mode)
```

也就是说，我们不是只在命令行里换了一个名字，而是在 PromptAD 的文本提示词构造阶段，把原本面向普通工业图像的类别名和异常描述，替换成了射频频谱图语义。

### 2.2 原始 PromptAD 的问题

原始 PromptAD 面向的是 MVTec/VisA 这类通用工业图像。它的异常模板更像：

```text
damaged {}
flawed {}
defective {}
{} with defect
{} with damage
```

这些词适合描述瓶子破损、金属划痕、胶囊缺陷等可见物体异常，但不适合频谱图。频谱图里没有“物体损坏”这个概念，异常通常表现为：

```text
信号能量异常
突发干扰
注入式射频干扰
时频结构异常
相对正常背景的能量偏离
```

因此，如果直接用原始 prompt，文本侧的 abnormal 语义和频谱异常的真实表现是不匹配的。

### 2.3 我们具体改了什么

第一，类别名不再使用场景名或普通类别名，而是统一为频谱图对象：

```text
radio frequency spectrogram
```

这样做是因为 `WeaponMuseum_spectrum`、`Playground_spectrum`、`TimeSquare_spectrum`、`Gymnasium_spectrum` 这些名字本质上是采集场景，不是异常检测目标。模型真正需要判断的是“这张射频频谱图是否正常”，而不是“博物馆/操场/时代广场/体育馆这个类别是否异常”。

第二，手工 abnormal prompt 从通用缺陷词改为 RF 异常词。当前 `prompt_mode=rf` 使用的异常模板为：

```text
abnormal {}
{} with anomalous signal energy
{} with unexpected interference
{} with injected radio-frequency interference
{} with abnormal time-frequency structure
{} with signal energy inconsistent with the normal background
```

代入统一类别名后，实际含义类似：

```text
abnormal radio frequency spectrogram
radio frequency spectrogram with anomalous signal energy
radio frequency spectrogram with unexpected interference
radio frequency spectrogram with injected radio-frequency interference
radio frequency spectrogram with abnormal time-frequency structure
radio frequency spectrogram with signal energy inconsistent with the normal background
```

第三，PromptAD 原有的可学习 prompt 机制仍然保留。代码中 prompt 会被拼成三类：

```text
normal prompt:
[SOS] + normal_ctx + radio frequency spectrogram + [EOS]

handcrafted abnormal prompt:
[SOS] + normal_ctx + RF abnormal suffix + [EOS]

learned abnormal prompt:
[SOS] + normal_ctx + abnormal_ctx + radio frequency spectrogram + [EOS]
```

其中 `normal_ctx` 和 `abnormal_ctx` 是可训练向量，不是普通英文单词。我们的改动是给这些可学习向量提供更合理的固定语义锚点：正常对象锚定在 `radio frequency spectrogram`，异常方向锚定在 RF 干扰、异常能量和异常时频结构上。

### 2.4 为什么这样改

这个改动的依据是频谱异常检测的任务属性。

第一，频谱图是时频能量图，不是自然图像或工业物体图像。原始 RGB 图像里看到的颜色通常只是功率/灰度的伪彩色映射，真正有意义的是时间轴、频率轴和能量分布。因此文本侧也应该描述“射频频谱图”和“时频结构”，而不是描述“损坏”“破裂”“瑕疵”这类物体外观词。

第二，当前研究设置中推理前不知道异常类型，所以 prompt 不能写成“这是 chirp 异常”或“这是 burst 异常”。因此主方案没有使用 `rf_signal_structured` 里那些按异常类型区分的模板，而是使用更通用的 `rf` 模式。它只描述 RF 异常的共同性质：异常能量、意外干扰、注入干扰、时频结构异常、偏离正常背景。

第三，PromptAD 的分类分数来自图像特征和 normal/abnormal 文本特征的相似度差异。如果 abnormal prompt 的语义与频谱异常不一致，文本原型会把图像拉向错误的语义方向。RF prompt 的目的就是让文本原型从“通用物体缺陷”转为“频谱信号异常”。

第四，这个改动保持了 PromptAD 的训练约束：训练阶段仍然只使用 normal 样本，不需要异常样本参与训练；测试阶段也不需要提前知道异常属于 burst、chirp 还是 dsss。因此它符合实际生产中“异常类型未知”的约束。

### 2.5 和输入特征改进的关系

RF 提示词负责文本侧的任务语义适配，`morph_fusion_gray_residual_a01` 负责图像侧的频谱结构表达。二者解决的是不同问题：

| 模块 | 解决的问题 |
|---|---|
| RF prompt | 让 normal/abnormal 文本原型更符合射频频谱异常语义 |
| gray_contrast | 增强低对比度频谱结构 |
| weak_residual(alpha=0.1) | 突出相对频率行背景的能量偏离 |
| original_gray | 保留原始频谱能量分布，避免增强图过度改造输入 |

因此，当前完整方案应该表述为：

```text
RF-domain prompt adaptation + structure-aware grayscale spectral input
```

而不是只写成单纯的特征提取方法。

## 3. 三个输入通道的含义

| 通道 | 实现名 | 含义 |
|---|---|---|
| 第 1 通道 | `gray_contrast` | 对原始灰度频谱图做局部结构增强 |
| 第 2 通道 | `weak_residual(alpha=0.1)` | 基于频率行背景中位数构造的轻量残差增强图 |
| 第 3 通道 | `original_gray` | 原始灰度频谱图 |

对应特征图示例如下：

![特征图示例](analysis_outputs/current_scheme_figures/gray_residual_feature_examples.png)

`gray_contrast` 用于增强低对比度结构，使弱频谱变化更容易被模型感知。该通道保留原图整体形态，但提高局部灰度差异。

`weak_residual(alpha=0.1)` 用于描述频谱图中相对于稳定背景的偏离。具体做法是：对每一条频率行估计时间方向的中位背景，再计算当前像素与该背景之间的差异，并以较小权重叠加回灰度图。这里使用 `alpha=0.1`，是为了避免残差过强导致正常背景纹理也被放大。

`original_gray` 用于保留原始频谱图的信息分布。加入这一通道的原因是，频谱图本身的能量形态仍然是重要信息，不能完全替换成增强图或残差图。

## 4. 方法动机

频谱图中的异常并不主要依赖颜色，而是依赖时频平面上的强度变化和结构变化。原始 RGB 图像通常来自灰度或功率图的颜色映射，三个颜色通道并不一定提供独立的物理信息。因此，本方案将 RGB 输入替换为三个更直接的频谱灰度视角。

该方法希望同时满足三个要求：

```text
保留原始频谱图的强度分布
增强弱异常和局部结构
不依赖异常类型先验
```

其中第三点很关键。实际应用中，模型在推理前通常不知道异常是 burst、chirp 还是 dsss，因此最终方案不能依赖“先判断异常类型，再选择特征提取方法”的流程。`morph_fusion_gray_residual_a01` 对所有纳入实验的异常类型使用同一个输入变换，因此更适合作为统一特征融合方案。

### 三个特征的公式表达

`original_gray`：

```text
I_gray = Gray(I_rgb)
```

`gray_contrast`：

```text
I_contrast = CLAHE(I_gray; clipLimit=2.0, tileGridSize=8×8)
```

`weak_residual(alpha=0.1)`：

```text
B(f) = median_t I_gray(f, t)
R(f, t) = |I_gray(f, t) - B(f)|
I_res(f, t) = Normalize(I_gray(f, t) + 0.1 * R(f, t))
```

## 5. weak residual 的计算

设原始灰度频谱图为 `I`，对每个频率行计算时间方向的中位数背景：

```text
B(f) = median_t I(f, t)
```

残差信息为：

```text
R(f, t) = |I(f, t) - B(f)|
```

最终的轻量残差图为：

```text
I_res(f, t) = normalize(I(f, t) + 0.1 * R(f, t))
```

这里的 `0.1` 是残差增强权重。实验中发现，较大的残差权重会增强部分异常，但也容易放大正常背景中的细纹和场景差异；较小权重能够更稳地补充异常偏离信息。

## 6. 实验结果

实验协议：

```text
数据集：自测频谱图数据集
异常类型：burst_signal, chirp_signal, dsss_signal
训练协议：normal_75_25
训练集：75% normal 样本
测试集：25% normal 样本 + 全部 abnormal 样本
seed：111
epochs：50
```

对比对象只保留两个：

```text
真正 baseline：原始 PromptAD，即 legacy prompt + RGB input
现有方案：RF 提示词 + morph_fusion_gray_residual_a01
```

主结果如下，指标为 Image-AUROC：

| 方法 | burst_signal | chirp_signal | dsss_signal | 三类平均 |
|---|---:|---:|---:|---:|
| 原始 PromptAD baseline (`legacy` + RGB) | 86.8375 | 78.9358 | 96.4792 | 87.4175 |
| 现有方案 (`rf` + `morph_fusion_gray_residual_a01`) | 90.0708 | 84.9758 | 96.6483 | 90.5650 |
| 提升幅度 | +3.2333 | +6.0400 | +0.1691 | +3.1475 |

与真正原始 PromptAD baseline 相比，当前方案在三类平均 AUC 上从 `87.4175` 提升到 `90.5650`，提升 `+3.1475`。

之前文档中出现过的 `RF prompt + RGB` 结果不再称为 baseline。它属于中间消融设置，不作为本文主结果表的对比对象。本文主结论只比较“原始 PromptAD”和“现有完整方案”。

## 7. 当前结论

`rf + morph_fusion_gray_residual_a01` 是当前更适合作为主线的方法。它的价值不在于单个场景里偶然多出几点，而在于它同时解决了 PromptAD 在频谱场景中的两个根本不匹配：文本语义不对、输入表达不对。

该方案可以概括为：

```text
RF 场景提示词 + 灰度保真 + 局部结构增强 + 轻量背景残差
```

从实验结果看，该方法能够在保持 DSSS 性能不低于 baseline 的同时，继续保留 burst 和 chirp 上的大部分提升。因此，当前后续实验、表格和文档都以该方案作为主推方案。

## 8. 公开数据补充验证

为了验证当前统一方案在公开协议上的表现，又补做了 `RF_SPE_PNG` 的正式对比实验。这里也统一采用和主实验一致的口径：

```text
真正 baseline = original PromptAD = legacy prompt + RGB input
现有方案 = rf prompt + morph_fusion_gray_residual_a01
```

公开数据协议不是四场景 `75/25`，而是：

```text
训练正常样本：/mnt/data/wangbei/data/RF_SPE_PNG/RF_Spectrum_Public_Dataset/ 中按目录排序后的前 k_shot=1 个 MeasRes_* 目录
测试正常样本：剩余 MeasRes_* 目录中的全部 patch
测试异常样本：
  burst -> /mnt/data/wangbei/data/RF_SPE_PNG/burst/abnormal/{m30db,m40db,m50db}
  chirp -> /mnt/data/wangbei/data/RF_SPE_PNG/chirp/abnormal/{m50db,m55db,m60db}
  dsss  -> /mnt/data/wangbei/data/RF_SPE_PNG/dsss/abnormal/{m20db,m30db,m40db}
seed = 111
epochs = 50
```

之所以把 `burst` 改成 `m30/m40/m50`，是因为 `m20db` 过于容易，而 `m50db` 已经验证现有方案仍有提升；把 `chirp` 改成 `m50/m55/m60`，则是为了避免旧的 `m20/m30/m40` 接近饱和。

正式结果文件位置：

```text
analysis_outputs/public_current_vs_original/public_current_vs_original.csv
analysis_outputs/public_current_vs_original/summary.md
```

公开数据 Image-AUROC 结果如下：

| 异常类型 | level 1 baseline | level 1 当前 | level 2 baseline | level 2 当前 | level 3 baseline | level 3 当前 |
|---|---:|---:|---:|---:|---:|---:|
| `burst` | 94.87 | 96.88 | 84.29 | 88.47 | 62.39 | 65.29 |
| `chirp` | 90.11 | 94.16 | 66.14 | 71.75 | 54.18 | 55.55 |
| `dsss` | 96.83 | 94.99 | 85.80 | 84.40 | 69.78 | 71.88 |

注：
- `burst` 的 `level1/2/3` 对应 `m30db / m40db / m50db`
- `chirp` 的 `level1/2/3` 对应 `m50db / m55db / m60db`
- `dsss` 的 `level1/2/3` 对应 `m20db / m30db / m40db`

按异常类型取三档均值后：

| 异常类型 | baseline 均值 | 当前方案均值 | 提升 |
|---|---:|---:|---:|
| `burst` | 80.52 | 83.55 | +3.03 |
| `chirp` | 70.14 | 73.82 | +3.68 |
| `dsss` | 84.14 | 83.76 | -0.38 |
| **总体均值** | **78.27** | **80.37** | **+2.11** |

这组结果说明：

1. `burst` 在 `m30/m40/m50` 三档上都是正收益，泛化稳定；
2. `chirp` 在更合理的高难度协议下继续保持明确增益；
3. `dsss` 在公开协议上仍然不够稳定；
4. 新的公开协议比旧版更能体现方法差异，因此更适合作为正式补充验证。

因此，公开数据可以支持一个更准确的结论：该方案并非只对自测数据有效；在更难的公开 `burst` 和 `chirp` 协议下，它相对原始 PromptAD 都有稳定增益。但 `dsss` 仍然提示我们，该方法的跨协议泛化还没有完全解决。

## 10. VCP dense map 补充诊断结果

在现有方案基础上，又补做了一组 VCP / dense mask supervision 诊断实验。这个实验不改变当前主方案的 Image-AUROC 结论，目的只是回答一个问题：

```text
如果 Image-level 分数继续使用原 PromptAD 分支，
VCP/dense 分支是否能提供更好的 Pixel-level anomaly map？
```

### 10.1 实验协议

该实验使用跨库设置：

```text
source:
  public RF source normal + abnormal + mask
  用于训练 VCP/dense mask branch

target train:
  project RF target train normal only
  用于构建 target normal gallery

target test:
  project RF target test normal + abnormal + mask
  用于最终评估
```

为了避免 Image-AUROC 被 anomaly map 的最大值污染，这里明确采用：

```text
Image ROC:
  raw image score only
  不再使用 harmonic(image_score, map_max)

Pixel ROC:
  只比较 anomaly map 本身
```

也就是说，本节实验只比较两种 map：

```text
original PromptAD map:
```

### 10.2 Pixel-AUROC 结果

| map source | burst px AUROC | chirp px AUROC | dsss px AUROC | all px AUROC |
|---|---:|---:|---:|---:|
| original PromptAD map | 50.77 | 28.51 | 80.55 | 53.28 |
| VCP/dense map | 46.24 | 50.42 | 88.96 | 61.87 |
| delta | -4.53 | +21.91 | +8.41 | +8.59 |

这组结果说明：

1. VCP/dense map 对总体 Pixel-AUROC 有明确提升，从 `53.28` 到 `61.87`；
2. 提升主要来自 `chirp` 和 `dsss`，其中 `chirp` 提升 `+21.91`，`dsss` 提升 `+8.41`；
3. `burst` 的 Pixel-AUROC 从 `50.77` 降到 `46.24`，说明 dense map 并不是对所有异常类型都更好；
4. 因此，VCP/dense 分支当前更适合作为 pixel-level localization 分支，而不是直接替代原 PromptAD 的 image-level scoring。

### 10.3 对架构的含义

这个实验支持一个更清晰的分工：

```text
Image-level anomaly detection:
  继续使用现有方案的原 PromptAD image score

Pixel-level anomaly localization:
  使用 VCP/dense map，或后续做 original map 与 dense map 的 gated fusion
```

因此，后续不应再直接把 `dense_map_max` 或 `dense_topk_score` 强行并入 Image-AUROC。更合理的方向是：

```text
final_image_score = original PromptAD image score
final_pixel_map   = VCP/dense map 或 gated(original map, dense map)
```

从当前证据看，VCP/dense 分支的价值主要体现在跨库异常区域定位，而不是稳定提升图像级异常判别。
