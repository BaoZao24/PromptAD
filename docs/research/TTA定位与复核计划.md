# TTA 定位与复核计划

## 当前决定

正式主线启用频谱 TTA，但只把它当作**辅助正常记忆扩充**：在正常 support 很少时，为正常
记忆补充合理采集变化的参考特征。它不是核心创新，不画进架构图，也不作为方法优越性的主要
论据。固定协议为原图、时间方向双向 `±4 px` 和频率响应漂移，视图合并进 ViT memory；测试
图保持原图查询一次，CNN 分支不使用 TTA。

论文的三项核心创新仍是：目标域免训练记忆学习、双尺度正常记忆库、support-only 置信度融合。

## 实验怎么处理

- 已有带 TTA 的 Ours 正式产物可以作为当前主线候选，但必须核对其是否使用上述冻结视图和
  memory layout；不符合的旧产物不能直接改名为当前主线结果；
- 所有使用 TTA 的论文表格或图，必须同时保留相同 support、相同测试集、相同随机种子的无 TTA
  对照；
- 已有无 TTA 对照的数据集可作为消融复用；缺少同划分主线结果时，补跑带 TTA 的 Ours，外部
  基线不因 TTA 配置变化而重跑；
- 报告结果时写清楚 TTA 仅在部分数据集或极少样本条件下有帮助，不能写成普遍提升；
- TTA 不参与 ViT/CNN 层选择、融合参数选择，也不再继续搜索新的变换组合。

## 代码口径

正式评估入口默认启用冻结的频谱 TTA；无 TTA 对照必须显式传入 `none`。每次运行都保存
`protocol.json`，记录 TTA 视图和 memory layout。TTA 只扩充正常参考，不更新 backbone 或融合
参数，也不使用异常样本或测试批次统计量。

## 接下来做什么

1. 盘点四个数据集是否已有与主表严格同划分的带 TTA 主线结果和无 TTA 对照；
2. 补齐缺失的带 TTA Ours 主结果，并更新 TTA 消融表；
3. 冻结带 TTA 的正式协议，不再新增 TTA 变体；
4. 把主要精力转向文献缺口核查和主线双尺度记忆库/置信度融合的消融证据。
