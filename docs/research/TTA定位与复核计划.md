# TTA 定位与复核计划

## 当前决定

保留频谱 TTA，但只把它当作**辅助正常记忆扩充**：在正常 support 很少时，为正常记忆补充
合理采集变化的参考特征。它不是核心创新，不画进架构图，也不作为方法优越性的主要论据。

论文的三项核心创新仍是：目标域免训练记忆学习、双尺度正常记忆库、support-only 置信度融合。

## 实验怎么处理

- 已有带 TTA 的 Ours 正式产物可以保留，不能为了文档改名而重跑全部实验；
- 所有使用 TTA 的论文表格或图，必须同时保留相同 support、相同测试集、相同随机种子的无 TTA
  对照；
- 已有无 TTA 对照的数据集直接复用；缺少对照时，只补跑 Ours 的无 TTA 一组，不重跑外部基线；
- 报告结果时写清楚 TTA 仅在部分数据集或极少样本条件下有帮助，不能写成普遍提升；
- TTA 不参与 ViT/CNN 层选择、融合参数选择，也不再继续搜索新的变换组合。

## 代码口径

代码默认保持 identity-only，避免不经说明地启用 TTA。需要复现已有 TTA 协议时，必须显式传入
对应参数，并将 `protocol.json` 与无 TTA 对照一起保存。TTA 只扩充正常参考，不更新 backbone
或融合参数，也不使用异常样本或测试批次统计量。

## 接下来做什么

1. 盘点四个数据集是否已有与主表严格同划分的无 TTA 对照；
2. 只补齐缺失的 Ours 无 TTA 对照，并更新 TTA 消融表；
3. 冻结包含或不包含 TTA 的每个正式协议，不再新增 TTA 变体；
4. 把主要精力转向文献缺口核查和主线双尺度记忆库/置信度融合的消融证据。
